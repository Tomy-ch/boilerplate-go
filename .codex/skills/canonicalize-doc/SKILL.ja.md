# 正本ドキュメントの同期

英語が正本であり、日本語はその訳である。作業対象は、確認の取れた 1 組のドキュメントペアだけとする。

## ペアを確定する

ファイルパスと方向が渡されたならそれを受け取る。どちらかが欠けている、または曖昧な場合は、周辺のパスだけを調べたうえで、ユーザーに次を指定してもらう。

- ソースファイル
- 方向: `canonical-from-translation` / `translation-from-canonical` / `sync-both`
- `sync-both` の場合、どちらを正とするか

対応するマッピング:

| ドキュメント種別 | 正本 | 訳 |
| --- | --- | --- |
| 同一ディレクトリの README / 一般 Markdown | `foo.md` | `foo.ja.md` |
| skill | `SKILL.md` | `SKILL.ja.md` |
| ドキュメントツリー | `docs/<path>/foo.md` | `docs/<path>/foo.ja.md` |

ペアを安全に確定できない場合は、先へ進まないこと。

### 訳側の読み取り

`AGENTS.md` はエージェントに `*.ja.md` を読むなと言っており、その規則が言っているのは知識の出所のことである。翻訳は原文に遅れるので、そこから考えると古い答えが出る。読むべきは canonical の英語版である。

このスキルの対象は対訳ペアそのもので、その理屈が覆わない唯一の場合になる。更新する側を読めない同期は、目隠しで上書きする（そこに既にある訳語と、2 つのファイルが共有している構造を捨てる）か、作業を差し戻すかしかない。後者は、1 世代遅れた翻訳の隣に canonical ファイルが出荷される道である。

この場合の例外は `AGENTS.md` が持っている。上の段落から推論するのではなく、そちらを読むこと。**この許可はこのスキルが与えるものではない。** ここで広げるものもない。対象は上で確認したペア、期間はこの実行の間、目的は変更の落ちる位置の特定と既存の訳語への追随に限られる。canonical は英語のままであり、翻訳がシステムに関する事実の出所になることはなく、確認したペアの外の `*.ja.md` は開かない。`AGENTS.md` にその例外がないなら、止めて人間に聞くこと。スキルがリポジトリの規則からの自己免除を宣言することは、規則の穴を回る近道ではなく `AGENTS.md` が禁じている loophole そのものである。

## 翻訳・同期する

1. ソースファイルを最後まで読む。`sync-both` の場合は両方を読む。
2. 見出し階層・リストの入れ子・リンク先・識別子・パス・コマンド・コードブロックを保つ。訳すのは散文だけである。
3. 正本 `SKILL.md` では、`name` と `description` の frontmatter を英語で妥当な状態に保つ。訳が存在する場合は `SKILL.ja.md` への短い案内を添える。
4. `SKILL.ja.md` では YAML frontmatter を置かず、`SKILL.md` から保守される訳であり単独で編集してはならない旨を述べる日本語の引用行で始める。
5. README および一般の訳では、英語側が正本である旨の簡潔な注記で始める。英語側からのリンクは、求められたときにだけ足す。

## 書き出しと検証

- 確認済みのソース / 対応ファイルのペア以外は変更しない。`AGENTS.md`・生成物・無関係な Markdown は決して触らない。
- 最終的な見出し構造と節数を突き合わせる。コードブロックは、その内部に意図して置かれた自然言語の散文を除き、バイト単位で一致していなければならない。
- 書き出したあと `make md-lint` を実行する。リポジトリ全体に及ぶ `make md-fix` は、無関係なファイルを書き換え得るため、明示的な承認なしには実行しない。
- 対応付けられなかった節や訳の不確かさは、推測で埋めずに報告する。

最後に、ソース・方向・変更したファイル・Markdown lint の結果を述べる。stage / commit / push はしない。
